Bibliographic & Research Overview: This journal article by Jong Yih Kuo, Shin Jie Lee, Chia Ling Wu, Nien Lin Hsueh, and Jonathan Lee, published in the International Journal of Fuzzy Systems (Vol. 7, No. 2, pp. 85 to 92, June 2005), proposes a unified evolutionary multi-agent framework for Intelligent Transportation Systems (ITS). Core Contribution: Newly instantiated software agents start with limited knowledge and low problem-solving capability. To enable agents to adapt dynamically in distributed ITS environments, the authors combine four complementary pillars: (1) a BDI-inspired four-module agent architecture, (2) Goal-Driven Use Cases (GDUC) with Zadeh's test-score semantics for fuzzy soft/rigid goals, (3) OWL and RuleML ontological reasoning for sub-goal refinement, and (4) a five-state multi-agent evolution cycle using Sugeno fuzzy inference, SOM-based selection, and inter-/intra-agent genetic restructuring, validated on a live Web-service-based ATIS hotel recommendation prototype.

Structural Map of the Paper: Section 1 (Introduction, p. 85) motivates Multi-Agent Systems (MAS) for geographically and functionally distributed ITS and defines four foundational requirements for agent evolution. Section 2 (Related Work, pp. 85 to 86) reviews MAS frameworks in ITS (2.1) and evolutionary agent algorithms (2.2). Section 3 (Evolutionary Agent Model, pp. 86 to 89) presents the BDI-based 4-module agent architecture (3.1), Goal-Driven Use Case analysis (3.2), and fuzzy soft/rigid goal formulation (3.3). Section 4 (Agent Evolution Mechanism, pp. 89 to 90) details the Sugeno fuzzy reasoning model (4.1), OWL/RuleML goal-driven ontology reasoning (4.2), and the 5-state evolution life cycle with SOM selection and GA restructuring (4.3). Section 5 (Case Study, pp. 90 to 91) implements an ATIS hotel/snack/scenery recommendation system over Web Services and reports 13 simulation scenarios (Table 3). Section 6 (Conclusion, p. 91) summarizes contributions.

Problem Statement (Section 1): In ITS services—such as route guidance, travel recommendation, traffic information provision, and vehicle assistance control—software agents act autonomously on behalf of travelers. However, newly spawned agents lack domain maturity. Addressing the four structural, reasoning, social, and evaluation pillars simultaneously is necessary so agents can evolve both their internal knowledge/beliefs and their structural plan modules over successive generations.

Literature Positioning (Section 2): Prior ITS multi-agent frameworks excel at decentralized traffic signaling and driver advisories, while prior evolutionary agent systems apply Genetic Algorithms, dynamic objects, or fuzzy rule learning independently. However, none tightly couple (a) formal Goal-Driven Use Cases with elastic fuzzy soft goals, (b) Semantic Web OWL/RuleML ontology refinement, and (c) SOM-guided genetic restructuring inside a unified BDI agent life cycle—the exact gap targeted by this paper.

Agent Mental Architecture (Section 3.1, Figures 1 and 2): Figure 1 maps the classic BDI mental states onto an evolutionary lifecycle: - Agent Creation occurs in the Goal Module, which queries the Ontology Management Module to interpret user preferences. Domain ontologies are annotated in W3C OWL (Figure 2 in the paper defines FunctionalProperty attributes for Hotel), while issue-specific ontologies capture weighted soft-goal decompositions (Figure 3: Quality -> Facilities 0.8, Space 0.7, Services 0.9). - Agent Growing occurs in the Belief Module via fuzzy and ontological reasoning, incorporating success/failure feedback from executed plans to adapt fuzzy rules. - Agent Selection and Restructuring occur in the Plan Module, feeding structural mutations and crossover updates back into the Goal and Belief modules.

Goal-Driven Use Cases & Fuzzy Semantics (Sections 3.2 and 3.3, Table 1, Figures 4a/4b): Using Lee & Kuo's GDUC methodology (1998, 2001), requirements are structured into a stable kernel use case ("getRecommendation") plus two extending alternative flows ("runAgain" if the user is unsatisfied, and "showExceptionMessage" on connection failure). Formal Mental State Transition: Each user goal g is formalized as a state transition <b, g, a> achieved by a plan <precondition, post-condition>. Using Zadeh's (1986) test-score semantics, imprecise traveler preferences become elastic constraints whose satisfaction degree is evaluated via membership functions: Interest spans [0, 100] (Low, Average, High) and Budget spans [0, 10000+] (Poor, Normal, Rich). A rigid goal is simply a boundary special case where membership must equal 1.0.

Unified Mechanism Overview (Sections 3.3 and 4.1 to 4.3): This synthesized diagram connects all four mathematical and symbolic stages of the paper: 1. GDUC Fuzzy Goals: Distinguishes elastic soft preferences (G1, G2) from hard budget ceiling (G3). 2. OWL + RuleML Ontology Refinement: Decomposes Quality(Hotel) using issue-specific relevance weights (Facilities 0.8, Space 0.7, Services 0.9) to derive refined sub-goals G21, G22, G23. 3. Sugeno Fuzzy Controller: Evaluates 9 heuristic rules (HR1 to HR9) over Max(Budget) and Min(Budget) to defuzzify a crisp hotel class demand degree DH. 4. GA + SOM Evolution: Encodes candidate recommendations as binary chromosomes (1 Hotel + 3 Snacks + 3 Sceneries) and evolves the population using weighted spatial distance fitness.

Fuzzy Rule Base & Semantic Refinement (Sections 4.1 and 4.2, Table 2, Figures 3 and 5): 1. Sugeno Fuzzy Reasoning (4.1): Extending Zimmermann's (1996) Sugeno controller, Table 2 maps the 3x3 combinations of Max(Budget) {Rich, Normal, Poor} and Min(Budget) {High, Average, Low} onto five linguistic Hotel Class degrees (Figure 5: VS, S, N, L, VL spanning [0.0, 1.0]). Crucially, the Ontology Management Module supplies domain knowledge to these fuzzy rules, while the agent's learning mechanism evolves the rules over time. 2. Ontological Reasoning (4.2): OWL provides shared semantic annotations across heterogeneous travel providers, while RuleML specifies inference rules. Multiplying edge relevance weights along a directed relation path quantifies semantic confidence, automatically refining abstract user desires (e.g., "High Hotel Quality") into evaluable attributes (Equipments, Space, Service).

Evolution Life Cycle & Genetic Mechanics (Section 4.3, Figures 6 and 7): Figure 6 formalizes an agent's complete lifespan across five states: - Chromosome Design (Figure 7): Each individual encodes a complete travel recommendation tuple—one hotel ID, three snack-place IDs, and three scenic-spot IDs—represented as binary strings over 1..N (e.g., 001 | 001 002 003 | 001 002 003). - SOM-Based Selection (Su, Zhao, & Lee, IJCNN 2004): Evaluates fitness via the weighted sum of GPS distances from candidate hotel H to selected scenic spots (Sc_i) and snack places (Sn_j), guiding convergence toward spatially convenient recommendations. - Dual-Level Restructuring: Supports both inter-agent module exchange (multi-point sorted crossover) and intra-agent parameter/strategy exchange, plus random gene replacement mutation. - Fault Tolerance (Illness State): Explicitly models security/integrity recovery when an agent is tampered with by malicious hosts or peers.

Prototype Architecture & Service-Oriented Integration (Sections 5.1 and 5.2, Figure 8): To validate the theoretical model, the authors implemented a working Java/JSP and Apache Axis Web Services prototype. Two Web Services query a GPS database for snack bars and scenic spots, while five dedicated Hotel Web Services scrape/query five target hotel websites for hotel name, room types, price, and live reservation status. Separating TPWS (fuzzy demand inference), WSS (external service aggregation), AEM (GA+SOM evolution), and ORM/OMS (ontological reasoning and knowledge storage) demonstrates practical SOA interoperability for distributed ITS.

User Interaction & Closed-Loop Workflow (Sections 5.1 and 5.3, Figure 9): Figure 9 shows the actual deployed JSP front-end running on Apache Axis (Client.jsp). Notice how the UI directly operationalizes the GDUC Table 1 specification: three ranked snack categories, three ranked scenic spot categories, minimum and maximum budget bounds, room type, and reservation date. Submitting the form triggers TPWS -> WSS -> AEM -> ORM -> JSP rendering, while allowing the traveler to re-run agent evolution if the returned itinerary does not meet expectations.

Empirical Evaluation Analysis (Section 5.3, Table 3): In Table 3, the authors tested 13 combinations of candidate pool sizes ranging from 100 to 292 snack places and 12 to 88 scenic spots. Evolution terminated once either 95% of agents shared identical fitness or 100 generations elapsed (mutation rate = 0.01). Key Quantitative Findings: - Fast Convergence: Every single scenario reached the 95% stability criterion in between 3 and 31 generations (median 11 generations), never hitting the 100-generation timeout. - Interactive Responsiveness: Execution times ranged from 125 ms (103 snacks / 12 sceneries, 3 gen) up to a maximum of 422 ms (256 snacks / 86 sceneries, 23 gen), proving suitability for real-time Web-based travel advisory. - Data Observation: Row 11 in Table 3 (256 snacks, 78 sceneries, 31 generations) reports 16 ms in the original printed table—likely a typographical artifact in the 2005 print (e.g., 516 ms or timer wrap)—which is transparently highlighted in teal on the chart.

Critical Evaluation & Research Context: From a 2005 software engineering and soft-computing perspective, this paper is notably forward-looking in uniting Semantic Web standards (OWL, RuleML), Web Services (Apache Axis), fuzzy goal modeling, and evolutionary computation into a working prototype. At the same time, an objective scholarly review notes three evaluation boundaries: (1) Table 3 reports only generations and milliseconds without optimality-gap comparisons against baseline heuristics; (2) the "Illness" security recovery state and long-term fuzzy-rule learning are designed architecturally rather than stress-tested experimentally; and (3) extending the spatial distance fitness function to include dynamic traffic delays and multi-agent negotiation over scarce hotel rooms remains future work.

Concluding Synthesis (Section 6): The paper demonstrates a cohesive blueprint for adaptive ITS agents: (1) model elastic user requirements as fuzzy soft/rigid goals; (2) refine goals semantically through domain- and issue-specific ontologies; (3) infer user demand degrees via Sugeno fuzzy control; and (4) continuously evolve agent recommendations through SOM-guided genetic restructuring. The deployed ATIS hotel recommendation prototype confirms that this hybrid symbolic-evolutionary pipeline runs cleanly within sub-second web interaction budgets.
